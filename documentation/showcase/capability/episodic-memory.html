Episodic Memory

The harness can remember something a user said and bring it back weeks later — safely, and without keeping it forever. Whether that counts as real "episodic" memory depends on what you mean by the word, which is exactly what this page works through.

The Scenario

  1. Mon

    A user mentions, mid-conversation, that their team is migrating off a legacy system. Nothing about the current task depends on it — but it's worth keeping.

  2. +0s

    Before it's kept anywhere, the fact is screened — the same way an email attachment gets scanned before you trust it. Nothing about this sentence looks like an attempt to plant a hidden instruction, so it's marked trustworthy and filed away.

  3. Day 1–20

    Nobody asks about it again. Like an unused muscle, its importance quietly fades a little each day it goes untouched.

  4. Day 21

    In a completely different conversation, the user asks something related. The fact resurfaces automatically — no one had to remind the agent it existed.

  5. Day 21

    Being recalled resets its clock — it's relevant again, so it stops fading for now.

What's Real, and Why "Partial"

Episodic memory usually means: memory of a specific thing that happened at a specific time — "the user told me X on Tuesday" — as opposed to semantic memory (general facts) or procedural memory (how to do something). Here's what actually exists and why this is called "partial" rather than "built."

What's real: a genuine memory system — remember a fact, recall it later, forget it, and improve it based on feedback. Two things make it more than a toy:

  1. Every memory is safety-scanned before it's trusted. Before anything gets remembered, it passes through a gate that scans for injected instructions and stamps where the fact came from. If something looks untrustworthy, it still gets written — for audit purposes — but it's quarantined and can never be served back to the agent. That's a real security property most memory systems skip entirely: they'd just remember whatever they're told.
  2. Memories fade on purpose. Nothing sticks around forever by default — each fact carries a weight that decays smoothly over time (roughly 5% a day it goes untouched) and is deleted outright once it fades below a threshold. That's the part that genuinely earns the word "episodic" — like human memory, not everything is kept with equal weight.

Why it's "partial," not "built": the system doesn't actually distinguish "this happened at a specific moment in a conversation" from "this is just a general fact worth knowing." It's one undifferentiated bucket of remembered facts, tagged with a free-text label, not a real timeline of events. So the honest way to say it: the harness has real cross-session memory with real safety and decay built in — it just doesn't structurally separate "episodes" from "facts" the way the term technically implies.

One more thing worth knowing: there's a more advanced mode (off by default) that makes recall smarter — matching by meaning rather than exact wording, and merging near-duplicate memories instead of piling up redundant ones. It exists in the code but isn't the default behavior.

  • KnowledgeMemoryService implements IKnowledgeMemory: RememberAsync / RecallAsync / ForgetAsync / ImproveAsync.
  • Writes pass through IMemoryWriteGate first — it scans, classifies trust, and stamps provenance. A node stamped untrusted is written (for audit) but IsRecallable filters it out of every future recall, permanently.
  • Recall is two-source: the in-session cache is checked first (sub-millisecond), and only falls through to a full graph traversal if the cache doesn't have enough results.
  • Decay is handled by MemoryDecayService: each memory node stores a numeric weight and a last_accessed_at timestamp; weight decays as weight × (1 − decayRate)^daysSinceLastAccess (default rate 0.05/day), and a separate prune pass deletes nodes once their weight drops below a configured threshold.
  • Memory keys are namespaced by tenant and user (memory:{tenant}:{user}:{key}), so recall can never cross a scope boundary even by accident.
  • The more advanced mode mentioned above is "harmonic memory": when enabled, writes are enriched with an abstraction and cue anchors, and can be consolidated against similar existing entries instead of always creating a new node. Off by default.

Why It Matters

This is what lets an agent feel like it "remembers you" across sessions — without either forgetting everything the moment a conversation ends, or turning into a liability that will happily remember whatever a bad actor tries to plant. Getting both of those right at once is the actual hard part; most systems pick one.
